# Criterios de revisión

Aplicar únicamente a la tarea actual. Catálogo de señales para investigar, no detector validado de autoría ni lista de fallos obligatorios. V = visual; I = interacción; C = código/DOM/estilos calculados; U = contexto de usuarios. Las referencias S corresponden al inventario de fuentes de la skill. Para declarar incumplimiento, comprobar el criterio vigente y sus excepciones.

## Resolver la crítica visual

Relacionar cada recomendación con una función: agrupación, lectura, prioridad, comparación, identidad o interacción. Si se pide «quitar IA slop», examinar patrones recurrentes y justificar qué tratamiento perjudica el encargo. El color morado, Inter, las tarjetas o un sidebar no son pruebas de autoría ni defectos por sí solos. Una misma receta minimalista aplicada a todo también puede resultar genérica.

Recomendar una dirección coherente con roles tipográficos, densidad, estructura y énfasis. Evitar proponer una paleta nueva cuando el problema es navegación. No sustituir una aplicación operativa por una landing page. Comparar escritorio en el tamaño suministrado; no añadir diseños móviles.

Evaluar contraste con datos efectivos y estados pertinentes. Si solo hay captura, marcar bajo contraste aparente como sospecha. Separar contraste medido de legibilidad tipográfica y de gusto por la paleta. No prescribir una escala exacta de fuentes o espaciado sin contexto y tokens del producto.
